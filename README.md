# JET MEDIA — лендинг

Статический сайт без сборки и зависимостей: чистые HTML, CSS и JavaScript. Заявки уходят в Google Sheets и Telegram через Apps Script.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Разметка, SEO- и OpenGraph-теги, JSON-LD |
| `styles.css` | Палитра и типографика брендбука, компоненты, адаптив |
| `script.js` | **CONFIG со всеми настройками**, переводы (RU/EN/TH), калькулятор, форма |
| `logo.png` | Логотип из брендбука, фон удалён |
| `favicon.svg` | Иконка сайта: фирменная дуга и монограмма |
| `og-image.png` | Превью для соцсетей, 1200×630 |
| `Code.gs` | Код для Google Apps Script (в репозиторий можно не загружать) |

## CONFIG — единственное место, где меняются цифры

Открываете `script.js`, самый верх файла:

```js
const CONFIG = {
  appsScriptUrl: "https://script.google.com/macros/s/AKfycb.../exec",

  uplift: { standard: 6, premium: 15 },   // прирост выручки, %
  staffRelief: 20,                        // снижение нагрузки на персонал, %
  launchDays: "1–3",                      // срок запуска
  trialMonths: 2,                         // бесплатный тестовый период, месяцев

  // Абонплата за ресторан + устройства сверх включённых, THB/мес (тариф Standard)
  pricing: {
    low:  { subscription: 1900, includedDevices: 2, extraDevice: 240 },
    high: { subscription: 5800, includedDevices: 2, extraDevice: 590 }
  },
  premiumMultiplier: 2,                   // Premium = Standard × 2
  sampleDevices: 10,                      // «средний ресторан» для карточек тарифов

  usdToThb: 35,                           // курс бата к доллару
  currency: "฿",

  sliders: {                              // границы и значения по умолчанию
    tables: { min: 5,   max: 50,    step: 1,  value: 20   },
    guests: { min: 200, max: 15000, step: 50, value: 1800 },
    check:  { min: 100, max: 5000,  step: 10, value: 850  }
  },

  defaultPeriod: "month",                 // "month" или "год"
  defaultSeason: "low",                   // "low" или "high"
  debug: false
};
```

Проценты пишутся обычными числами: `6` — это 6%, а не `0.06`. Цены — в батах.

### Как считается стоимость

```
Standard = абонплата сезона + (устройства − включённые) × доплата за устройство
Premium  = Standard × premiumMultiplier
```

Пример из схемы монетизации: ресторан на 10 устройств в низкий сезон платит
`1900 + 8 × 240 = 3820 ฿/мес` по Standard и вдвое больше по Premium. Тарифы
отличаются только набором функций и рекламой — цена Premium всегда ровно
вдвое выше, отдельно её задавать не нужно, формула считает сама.

| Что меняете | Где меняется на сайте |
|---|---|
| `uplift.standard` / `uplift.premium` | подписи «+6%» / «+15%», расчёт прироста, чистый результат |
| оба `uplift` | диапазон «+6–15% к выручке зала» на первом экране |
| `staffRelief` | первый экран и карточка в блоке «Что получает ресторан» |
| `launchDays` | первый экран |
| `trialMonths` | сноска под тарифами |
| `pricing.*.subscription` | абонплата в калькуляторе и в карточках тарифов |
| `pricing.*.includedDevices` | подзаголовок тарифов и порог доплаты в расчёте |
| `pricing.*.extraDevice` | доплата в калькуляторе и в сноске под тарифами |
| `premiumMultiplier` | цена Premium везде |
| `sampleDevices` | цена-пример в карточках тарифов и подпись под ней |
| `sliders` | границы, шаг и стартовые значения ползунков |

В разметке этих чисел нет: элементы помечены атрибутом `data-claim`, значения подставляет `renderClaims()`. Если после правки CONFIG цифры на сайте не изменились — почти наверняка `index.html` остался от старой версии; в консоли браузера в этом случае появится предупреждение.

Единственное исключение — `og-image.png`: проценты там нарисованы в пикселях, превью надо перерисовывать отдельно.

## Калькулятор

Считает по обоим тарифам сразу:

- **Прирост выручки** — от `uplift` выбранного тарифа;
- **Абонентская плата** — абонплата сезона плюс доплата за устройства сверх включённых (одно устройство на столик);
- **Чистый результат** — разница. Если уходит в минус, число подсвечивается красным: для маленького зала в высокий сезон это честный ответ.

Переключатель **Месяц / Год** умножает все результаты на 12. Ползунки остаются месячными: они описывают обычную работу зала.

Переключатель **сезона** в калькуляторе и в блоке тарифов — один и тот же: нажатие в любом месте меняет и цены в тарифах, и аренду в расчёте.

## Публикация на GitHub Pages

1. Загрузите файлы в корень ветки `main`.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Замените `https://jetmedia.example/` в `canonical`, `og:url` и JSON-LD на реальный адрес.

GitHub Pages кеширует файлы. После заливки обновлённого `script.js` открывайте сайт с `Ctrl+F5` (или `Cmd+Shift+R`), иначе браузер покажет старую версию.

## Заявки: Google Sheets + Telegram

Схема: сайт → веб-приложение Apps Script → строка в таблице + сообщение в Telegram. Токен бота хранится в свойствах скрипта на стороне Google и в исходники сайта не попадает.

1. Создайте таблицу Google Sheets, например «JET MEDIA — заявки».
2. Расширения → Apps Script. Замените содержимое на `Code.gs` из этого проекта.
3. Впишите `BOT_TOKEN` и `CHAT_ID` в функцию `setup()` и запустите её один раз.
4. Запустите `testSend()` — в Telegram придёт сообщение, в таблице появится строка.
5. Развернуть → Новое развёртывание → «Веб-приложение».
   **Запуск от имени:** от моего имени. **У кого есть доступ:** у всех.
6. Скопируйте URL (заканчивается на `/exec`) в `CONFIG.appsScriptUrl`.

### Как заявка доходит до Telegram

Сайт пробует три канала по очереди и останавливается на первом сработавшем:

1. **JSONP** — ответ Apps Script загружается обычным тегом `<script>`. Такой запрос не подчиняется правилам CORS вообще, поэтому работает и в обычном браузере, и в WebView внутри Telegram, и при этом возвращает подтверждение от сервера. Основной канал.
2. **GET через fetch** — если у ответа есть заголовки CORS.
3. **POST без чтения ответа** — последняя попытка: подтверждения не будет, но заявка дойдёт.

Для первого канала `Code.gs` отвечает на параметр `callback`. Если вы обновляете `Code.gs`, обязательно разверните **новую версию** веб-приложения, иначе ответа не будет и сайт свалится на запасные каналы.

### Если форма не отправляет

Сначала выполните в консоли браузера (F12 → Console):

```js
JM.diagnose()
```

Команда печатает по шагам: правильный ли адрес, ответил ли скрипт, и что проверить дальше. Дальше — по списку, почти всегда дело в одном из пяти пунктов:

1. **Старое развёртывание.** Правки `Code.gs` не действуют, пока не нажали: Развернуть → Управление развёртываниями → карандаш → Версия **«Новая версия»** → Развернуть. Функция `testSend()` при этом работает — она запускает свежий код напрямую, минуя веб-приложение. Именно поэтому тест внутри редактора может проходить, а сайт получать ошибку.
2. **Доступ к веб-приложению.** Нужно: запуск **от моего имени**, доступ **«У всех»**. При доступе «Только я» браузер посетителя получает страницу входа Google вместо ответа.
3. **Адрес `/dev` вместо `/exec`.** Первый работает только у владельца в залогиненном браузере.
4. **Адрес не подставлен в CONFIG.** Тогда на странице появится отдельное сообщение «Форма пока не подключена к приёму заявок», а в консоли — красная строка с подсказкой.
5. **Старый `script.js` на сайте.** GitHub Pages кеширует файлы: после заливки открывайте с `Ctrl+F5`.

Проверка веб-приложения без сайта — откройте в браузере:

```
<ваш /exec>?name=Тест&phone=+66000000000&restaurant=Test
```

Должно ответить `{"ok":true}`, в таблицу упасть строка, в Telegram прийти сообщение.

Вместе с контактами уходит снимок калькулятора: столики, гости, чек, прирост по обоим тарифам, выбранный сезон и период.

Если Apps Script не нужен, заполните `botToken` и `chatId` в CONFIG — сайт обратится к Bot API напрямую. На статическом хостинге токен при этом виден любому посетителю.

## Языки

Все тексты в объекте `I18N` (`ru` / `en` / `th`), 106 ключей на язык. Чтобы добавить язык: скопируйте блок, переведите значения, добавьте кнопку в шапке и локаль в `LOCALES`.

```html
<button type="button" class="lang-btn" data-set-lang="zh">ZH</button>
```
